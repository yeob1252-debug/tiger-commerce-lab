# 타이거커머스랩 홈페이지 제작 최종 스킬 문서 v4

이 프로젝트(`tiger-commerce-lab`)의 코드 작업 시 항상 이 문서를 기준으로 삼는다.

## 0. 절대 규칙 — 반복됐던 심각한 오류 재발 방지

- **0-1.** 레퍼런스 사이트는 "확인했다"고 말하기 전에 반드시 실제로 확인한다 — 스크린샷/캡처 설명만 보고 단정하지 않는다. 실제 URL이 있으면 직접 열어서(가능하면 페이지 텍스트 통째 추출) 실제 존재하는 요소만 근거로 삼는다. 확인 안 된 부분은 "확인 안 됨"이라 명시하고, 확인된 것만 반영한다.
- **0-2.** 사용자의 최종 지시를 임의로 재해석하지 않는다 — 확정된 내용(색상, 문구, 구조, 이미지 유무 등)을 다음 턴에서 슬쩍 바꾸지 않는다. 바꿔야 할 이유가 생기면 이유를 명시하고 확인받은 뒤에만 바꾼다.
- **0-3.** 매 결과물 전 자체 점검(최소 2회): 1) 이번 요청에서 명시한 내용을 전부 반영했는지 항목별 대조 2) 과거 반복 실수 목록과 대조해 재발 여부 확인 — 문제 있으면 보여주기 전에 스스로 수정.
- **0-4.** AI 이미지 생성의 한계를 인지: 로고·심볼처럼 정밀한 기하학적 대칭이 필요한 요소는 AI 생성 대신 웹폰트 텍스트나 직접 코딩한 SVG로 만든다. 3D 아이콘 생성 프롬프트 끝에는 항상 "no text, no numbers, no labels, no watermark"를 명시한다.
- **0-5.** 실제 코드를 보지 않고 CSS 클래스명을 추측하지 않는다 — 스타일 지시가 2회 이상 반영 안 되면 실제 HTML/CSS 코드를 요청해서 받은 뒤 정확한 선택자로 지시한다.

## 1. 디자인 시스템 원칙

- 대제목/부제목/본문 3단계의 크기·굵기 위계는 항상 통일하고 섹션마다 다르게 쓰지 않는다.
- 색상은 반드시 실제 hex 값으로 명시한다.
- 텍스트 블록은 항상 이미지/아이콘과 짝을 이루게 한다.
- 여백을 충분히 주고, 스케일 대비로 시선 위계를 만든다.
- 같은 그리드 안 이미지는 동일 비율로 크롭한다.
- 모바일 반응형은 브레이크포인트별로 구체적으로 확인한다.

## 2. 반응형 인터랙션

- 카드: 호버 시 위로 떠오름(translateY)+그림자 확대, 스크롤 진입 시 순차 등장(stagger).
- 숫자: 카운트업 애니메이션. 그래프: 스크롤 시 차오름 — 단, 그래프 틀(축·배경)은 고정, 데이터(선/수치)만 애니메이션 되어야 한다(틀+데이터가 동시에 나타나면 안 됨).

## 3. 지시문/작업 규칙

- 한글 텍스트는 전역 CSS `word-break: keep-all` 적용.
- 외부 링크는 `<a target="_blank">`로 구현.
- 폼→구글시트 연동은 Apps Script doPost 방식, 실제 시트 반영까지 테스트 확인.

## 4. 레퍼런스 사이트 참고 패턴

(heynesh.com, matgamsa.com, funnellab.co.kr, sdipresence.com, thepatchsystem.com/ai, orionix.framer.website)

- 신뢰 지표(파트너 로고 스트립 또는 "0→87%" 카운트업)를 상단에.
- 서비스/프로세스는 01~05 큰 번호 + 짧은 태그(pill).
- 문제 제기는 아이콘+짧은 문장 카드 3~4개 그리드.
- 가격 카드 3개 중 최소 하나는 "상담 문의" 버튼으로 대체 가능.
- FAQ는 번호형 아코디언.
- CTA 버튼은 여러 지점에 반복 배치.
