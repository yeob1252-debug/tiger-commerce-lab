# TIGER 매장 맞춤 제안서 운영 매뉴얼 v2.1

## 목적과 상태

- 매장 정보 brief를 검증된 5영역 제안서 JSON으로 변환한다.
- 생성 결과는 로컬 검수본이며 자동 게시, 계약, 결제, 고객 집계가 아니다.
- 제공 사실과 운영 제안을 구분하고 매출·조회수·방문·성과를 보장하거나 만들어 넣지 않는다.
- 업체별 제안서는 `noindex,nofollow,noarchive`를 유지하고 공개 메뉴와 사이트맵에 노출하지 않는다.

## 대표가 제공할 기초 정보

대표는 알고 있는 매장 정보를 자유문장으로 전달한다. 완성된 제안 원고나 분석표를 작성할 필요가 없다.

- 매장명, 지역, 업종·대표 메뉴
- 현재 상황과 원하는 목표
- 갖고 있는 경우에만 공식 홈페이지·네이버 플레이스·SNS URL, 메뉴·매장 자료, 운영 가능 범위와 예산

모르는 항목은 생략하거나 `미확인`이라고 적는다. 짧은 붙여넣기 예시는 다음 정도면 충분하다.

```text
매장명은 OO식당, 부산 남구에서 한식을 운영합니다. 대표 메뉴는 제육볶음이고
평일 저녁 손님에게 더 알려지고 싶습니다. 인스타그램 주소는 모르겠고 예산도 아직 미정입니다.
```

확인된 정보가 적더라도 담당자는 그 범위에서 가능한 제안 초안을 작성한다. 부족한 사실만 `확인 필요`로 표시하며, 가격·성과·방문 경험을 만들거나 자료 부족을 이유로 원고 작성 자체를 대표에게 돌리지 않는다.

## Codex·담당자가 작성할 정규화 제안 brief

담당자는 대표의 자유문장과 제공 자료를 다음 내부 입력으로 정리한다.

1. 제공 사실과 출처, 추정·제안, 확인 필요 항목의 분리
2. 확인된 강점과 보강 우선순위 3개
3. 매장 목표에 맞는 채널 역할과 선택 근거
4. 맞춤 후킹과 콘텐츠 예시
5. 첫 달 실행 순서와 각 단계의 근거
6. 목표·예산·운영 가능 범위가 확인된 경우에만 추천 플랜과 근거

`data/proposals/proposal-brief.template.json`은 대표 입력 양식이 아니라 담당자가 완성하는 **내부 정규화 입력 템플릿**이다. 검수용 가상 입력은 `data/proposals/briefs/test-neighborhood-table.json`이며 운영 배포 대상에서 반드시 제외한다.

실행 흐름:

1. 대표가 매장 정보를 자유문장으로 제공한다.
2. Codex·담당자가 사실·확인 필요·제안을 분리하고 맞춤 제안 원고를 작성한다.
3. `tools/create-proposal.mjs`가 정규화 brief를 검증하고 기존 5영역 JSON으로 조립한다.
4. 로컬 미리보기에서 대표가 검수한 뒤 별도 승인이 있을 때만 배포한다.

생성 스크립트는 AI 분석 엔진이나 실시간 외부조사 도구가 아니다. 담당자가 작성한 정규화 brief의 형식·안전 조건을 검증하고 기존 렌더러용 JSON으로 조립하는 단계다. 자동 매출 예측, 자동 플랜 추천, 외부 사실 확인을 수행하지 않는다.

## 고정 영역과 가변 영역

고정:

- 5영역 순서: `proposal-analysis` → `proposal-priorities` → `proposal-tailored` → `proposal-pricing` → `proposal-contact`
- 브랜드 디자인, 반응형 구조, CTA 구조, 가격표, VAT·계약기간 표시
- 가격과 플랜 구성의 유일한 정본은 `data/proposals/_common.json`
- 히어로의 호랑이 얼굴 프레임과 전체 얼굴 크롭

매장마다 바뀜:

- 핵심 후킹, 확인된 강점과 출처, 문제와 추정의 구분
- 보강 우선순위 3개와 근거
- 콘텐츠 예시, 채널 역할, 첫 달 계획
- 목표·예산·운영 범위에 근거한 추천안

추천 근거가 부족하면 플랜은 비워 둔다. 이 경우 화면은 `추천 운영안은 확인 후 함께 정합니다.`로 표시되며 특정 플랜을 강조하지 않는다.

## 배경과 발톱 규칙

- 히어로 `#hero`, `#section-01`에는 신규 줄무늬와 발톱을 표시하지 않는다.
- 줄무늬는 승인된 `tiger-body-stripes-mask-v3.png`를 본문 배경에만 사용한다. 스크롤 위치에 따라 무늬 내부의 호박빛만 바뀐다.
- 발톱은 승인된 `tiger-claw-tears-mask-v3.png`를 최상단 장식 레이어에서 0.68초 동안 한 번만 reveal 후 완전히 지운다.
- 홈 위치: `#what-we-do`, `#plans`, `#contact`.
- 제안서 위치: `#proposal-tailored`, `#proposal-pricing`, `#proposal-contact`.
- 발톱은 `pointer-events:none`, `aria-hidden=true`이며 버튼·입력·문서 높이·본문 transform을 바꾸지 않는다.
- 섹션을 벗어나거나 히어로로 돌아가면 즉시 소거한다. 폼이나 대화상자에 입력 중일 때는 재생하지 않는다.
- 모바일에서도 같은 위치에 한 번만 재생한다. `prefers-reduced-motion`과 인쇄에서는 발톱을 숨기고 전체 정적 내용을 즉시 표시한다.

## 생성 명령

```powershell
node tools/create-proposal.mjs --input data/proposals/briefs/{brief-file}.json
```

결과:

- JSON: `data/proposals/{slug}.json`
- 미리보기: `http://127.0.0.1:5191/proposal.html?slug={slug}`

입력 검증:

- slug는 영문 소문자·숫자·하이픈만 허용한다.
- `<`, `>`, 제어문자, 잘못된 URL을 거부한다. 화면 렌더러도 모든 문자열을 HTML escape한다.
- 기존 고객 JSON은 어떤 경우에도 덮어쓰지 않는다.
- 추천 플랜은 `_common.json`의 ID와 기간만 허용하며 추천 근거가 필수다.

핵심 보호 검사는 다음 명령으로 확인한다.

```powershell
node tools/create-proposal.mjs --self-test
```

## 검수와 배포

1. 생성된 로컬 URL에서 PC와 모바일의 5영역, 가로 넘침, 호랑이 얼굴, 가격·VAT·기간, 상담 CTA 문맥을 확인한다.
2. 제공 사실과 제안, 확인 필요 항목이 섞이지 않았는지 대표가 검수한다.
3. 인쇄 미리보기에서 모든 영역과 가격표가 보이고 발톱·애니메이션 대기가 없는지 확인한다.
4. 대표 승인 전에는 원격 push와 운영 배포를 하지 않는다.
5. 승인 후에도 공개 경로와 접근 범위를 별도로 확정한 뒤 배포한다.
